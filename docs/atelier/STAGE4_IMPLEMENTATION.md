# 4단계: 수동 작업실

2026-10-30, 기존 main 미커밋 1~3단계 위에서 구현. 원본 `atelier/atelier`와 history.json은 수정하지 않았다.

## 구현

`src/features/atelier`의 실제 WS 클라이언트·React 편집기를 기존 단일 useBridge 소켓에 연결했다. 네 시작 경로, 여덟 탭, 동일 데이터의 가이드/상세 편집, 원본/영역/실제 PNG 크롭, 로컬 FontFace, 범위와 의도 확인, 불변 프롬프트/JSON/ZIP, 수동 결과/검토/수정 계획/새 프롬프트를 제공한다. 저장 버튼은 서버 응답 후에만 저장됨으로 표시한다. 초안과 서버 기준은 분리하고 충돌 시 비교·명시 적용이 필요하다. 탭·프로젝트·질문 그룹·기준·검토 위치와 텍스트 초안을 복원한다. 선택한 File 객체는 열린 작업실에서 보존하며 브라우저 재시작 후에는 다시 선택해야 한다.

원본은 DOM·HTTP 중심이고 현재 저장소는 worker SQLite·엄격한 WS이므로 편집 UI를 그대로 실행하지 않고 공유 도메인과 저장 계약을 연결했다. 기존 도메인의 선택적 history 필드는 undefined를 포함하므로 JSON 검증에서 객체의 부재 필드를 직렬화 규칙대로 생략한다. 배열/외부 필드/한도 검증은 유지한다. 실제 font MIME 검증과 결과 근거 변경 시 기존 검토의 재검토 표시를 추가했다.

## 경계와 복구

R2: 브라우저와 파일 입력은 비신뢰이며 bridge의 프로젝트 소유·버전·파일 hash·MIME·범위 검증을 거친다. 일반 Codex 실행·승인·Team/Solo·대화·픽셀을 유지한다. 추가 외부 서비스·패키지·배포 없음. 신규 DB와 실제 파일은 기존 .local-data 아래에만 저장한다. UI 롤백은 기존 데이터를 삭제하지 않는다. 5단계 전제는 이 수동 왕복 검증이며 AI가 없는 상태를 성공으로 표시하지 않는다.
