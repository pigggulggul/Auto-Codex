# 아이디어부터 시작하는 작업실 개선

변경 범위는 R2(제안 요청 계약·응답 처리 포함)다. 기존 작업 트리의 변경을 유지했고 DB·백업 포맷·설계 확정 조건은 변경하지 않았다.

## 사용자 흐름

- 아이디어 한 문장으로 생성 → 기본 질문 3개 → AI 후보 확인 → 원하는 항목만 설계에 반영 → 이용 순서·분위기·자료를 필요할 때 추가한다.
- 탭은 아이디어 정리 / 이용 순서 / 참고 이미지 / 분위기 정하기 / 색·글자와 자료 / 설계 요약 / 만들기 준비 / 결과 확인·수정으로 표시한다. 저장용 tab ID는 유지한다.
- 차근차근 보기는 기본 입력을 보여 주고 선택·고급 입력을 접는다. 전체 항목 보기는 기존 항목을 펼친다. 숨긴 값과 브라우저 초안은 유지한다.
- 각 단계의 목적·예시·다음 행동, 항목별 설명, 체크박스 다중 선택, 빈 대상에서 항목을 준비하는 경로를 제공한다. 이동에는 서버 저장을 요구하지 않는다.
- AI의 네 가지 목적과 추가 도움 요청을 제공한다. 요청에는 현재 아이디어·답변·기능·콘텐츠·화면·흐름·컨셉·스타일·자료를 포함하며 과거 결정 이력은 제외한다. 이미지는 전달하지 않는다. 받은 후보는 접어 보관하고 새 요청 시 펼친다.
- 백업은 일상 저장과 다른 설계·첨부 복사본임을 설명한다. 준비와 장치 저장을 구분하고, 제안·제작 연결 기록 제외 및 자동 제작 결과가 있을 때의 제한을 안내한다.

## 오류와 신뢰 경계

보호 자산은 설계 원본, 미저장 초안, 로컬 파일, 실행 권한이다. 브라우저 입력과 모델 출력은 비신뢰 데이터다.

- 다운로드 준비를 반복하면 이전 전송이 남아 두 개의 전송 자리를 소모했다. 새 준비·닫기·프로젝트 전환·삭제·언마운트 시 정리하며, 배경 파일/프로젝트 읽기는 전체 다운로드 단위로 순차 처리한다. 크기 초과 거부 시에도 전송을 정리한다. 기존 연결별 2개/전체 8개 제한과 소유권 검사는 유지한다.
- AI 완료 이벤트의 비어 있는 content가 text를 가리거나, 진행 메시지와 최종 답변이 섞일 수 있었다. 메시지 ID와 phase를 구분하고 final_answer를 우선하며 빈 content는 실제 text로 보완한다.
- 단일 JSON 코드 블록만 벗겨 동일한 서버 검증에 통과시킨다. 임의 문장 속 JSON 추출, 잘못된 구조 수리, 외부 ID·status 등 권한 필드 수용은 하지 않는다. 모델 출력 스키마에도 문자열 길이와 근거의 최소 길이를 명시한다.
- 추가 도움 요청은 길이를 서버에서 검사한 설계 자료다. 도구 실행 권한이 아니다. 기존 readOnly/네트워크 차단/승인 거부, 대상 소유권·버전·revision 검증, 후보별 명시적 반영을 유지한다. 자동 확정과 자동 재시도는 없다.

## 검증과 적용

- `npm run typecheck`, `npm test`, `npm run build`를 실행한다. 테스트는 전송 중첩·초과 정리, 필드 안내·선택 접근성, fenced JSON의 허용/거부, commentary/final/빈 content 및 delta 전용 응답을 포함한다.
- `node tools/verify-atelier-guided-ui.mjs <playwright 패키지 경로>`는 자체적으로 `.cache`에 격리 저장소와 합성 App Server를 만들고 127.0.0.1:4877에서 실행한다. 실제 모델·사용자 저장소를 사용하지 않으며 외부 HTTP 요청은 차단한다. 기본 3문항, 백업 4회 반복 준비와 다운로드, 빈 제안 대상 준비, 후보 반영, 8개 탭, 390px 가로 넘침, 보기 전환 시 값 보존과 페이지 오류를 확인한다. 증거와 스크린샷은 `.cache/atelier-guided-ux/`에 남긴다.
- 테스트 최초 실행은 Windows 샌드박스 임시 파일 rename EPERM으로 시작하지 못했고, 허용된 환경에서 실행했다. 브라우저 도구는 기존 인스턴스 점유로 사용할 수 없어 별도 headless 브라우저를 사용했다. 샌드박스의 loopback 차단은 승인된 검증 실행 환경에서 해결했다.
- 실제 계정·모델에 따른 응답 품질과 사용성 인터뷰는 이 합성 검증의 범위가 아니다.
- 적용은 UI와 브리지를 함께 빌드하고 재시작한다. 배포·운영 데이터 변경은 없다. DB 마이그레이션이 없어 코드 복귀와 재빌드로 되돌릴 수 있으며 기존 설계·제안 기록은 보존한다.
