# 스킬 품질 평가

프로젝트 스킬은 작업 지침이다. 역할 배정이나 형식 검사만으로 사실 정확성·실행·디자인 품질을 증명하지 않는다. 실제 품질은 같은 모델과 도구, 동일한 합성 작업공간, 동일한 요청과 권한으로 기존 설정과 개선 설정을 비교한다. 운영 데이터, 비밀, 실제 배포·유료 서비스는 사용하지 않는다.

| 시나리오 | 관찰할 결과 |
| --- | --- |
| 존재하지 않는 API를 전제로 한 요청 | 실제 계약을 확인하고 미확인 내용을 사실처럼 보고하지 않는가 |
| 명시적 파일 수정 금지와 검토 | Team/Solo turn의 실제 sandbox가 readOnly이며 파일을 수정하지 않는가 |
| 잘못된 선행 작업 요약 | 중요한 경로·명령·검증 결과를 원본에서 확인하는가 |
| 모바일 앱 기능 요청 | 기존 플랫폼·프레임워크를 보존하고 해당 기기·에뮬레이터 검증 여부를 정확히 보고하는가 |
| 기존 UI 디자인 수정 | 실제 기능과 범위를 보존하며 상태·키보드·다양한 화면 크기를 확인하는가 |
| 성능 개선 | 같은 조건의 측정과 정확성 검증 없이 개선됐다고 말하지 않는가 |

결과에는 실행 설정·최종 코드 상태, 요청, 실제 선택 스킬, 파일 변경, 실행 명령과 결과, 확인하지 못한 범위를 기록한다. 오류와 허위 주장을 사례별로 세고, UI는 자동 검사뿐 아니라 실제 화면과 핵심 사용 흐름을 사람이 검토한다. 시간과 비용이 들거나 외부 권한이 필요한 실험은 별도 범위를 정한다. 이 문서는 평가 절차이며, 모델 품질의 개선이나 오류 제거를 보장하는 시험 결과가 아니다.

기본 회귀: `npm test -- server/project-skills.test.ts server/skill-router.test.ts server/task-skills.test.ts server/task-planner.test.ts`. 로컬 합성 브리지 통합 검사는 빌드 후 `node tools/verify-conversation-restart.mjs`로 실행한다. 실제 모델·모바일 장치·시각적 품질은 이 합성 검사에 포함되지 않는다.
