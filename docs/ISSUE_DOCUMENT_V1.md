# 이슈 교환 문서 v1 계약 초안

이 문서는 이슈 문서 파서의 계약을 설명한다. 사용자가 네이티브 선택창에서 고른 문서는 브리지에서 읽고 검증한 뒤 내부 이슈 저장소에 원자적으로 등록한다. 등록된 문서의 이슈는 프로젝트 폴더를 다시 확인한 소켓에서 볼 수 있으며, 선택한 문서를 프로젝트 안의 새 Markdown 파일로 내보낼 수 있다.

## 파일과 데이터

- UTF-8 Markdown 문서 전체는 최대 4 MiB다. 초과 시 전체를 거부한다.
- `auto-codex-issues-v1` 정보 문자열을 가진 fenced JSON 블록이 정확히 하나 있어야 한다. 지원하지 않는 이슈 문서 버전, 미완성 블록, 복수 블록은 거부한다. 다른 코드 블록 안의 예시는 데이터 블록이 아니다.
- 블록 밖의 설명은 교환 데이터가 아니다. JSON의 중복 키, 알 수 없는 필드, 잘못된 UTF-8과 64단계를 넘는 JSON 중첩을 거부한다.
- 최상위 필수 필드는 `format`, `formatVersion`, `documentId`, `revision`, `sources`, `categories`, `requirements`, `issues`다. 형식은 각각 `auto-codex-issues`와 `1`이다.
- 식별자는 최대 128자로 영문자·숫자로 시작하며 이후 영문자·숫자·`.`·`_`·`:`·`-`만 허용한다. 문서와 포함된 모든 객체의 ID는 서로 중복될 수 없다. 표시 이름과 개발 버전은 ID가 아니다.
- `revision`은 1 이상의 안전한 정수, `order`는 0 이상의 안전한 정수다. 제목·자료 이름은 최대 255자, 출처 위치는 최대 1024자, 일반 본문 문자열은 최대 32768자다. 한도 초과는 부분 성공이 아닌 오류다.

## 객체

- `sources`: `id`, `name`, `contentHash`가 필수다. 해시는 `sha256:`과 소문자 16진수 64자리다. 문서에는 원본 내용이나 절대 경로를 넣지 않는다.
- `categories`: `id`, `parentId`(ID 또는 null), `title`, `order`가 필수다. 상위 분류는 같은 문서에 있어야 하며 분류 계층의 순환을 허용하지 않는다.
- `requirements`: `id`, `categoryId`(ID 또는 null), `text`, `origin`이 필수다. `origin`은 `source`, `user`, `ai-proposal` 중 하나다. `source`에는 같은 문서의 `sourceId`가 필수이며, `sourceId`와 `locator`는 다른 유형에서 선택 사항이다.
- `issues`: `id`, `categoryId`(ID 또는 null), `requirementIds`, `version`, `order`, `title`, `description`, `acceptanceCriteria`, `dependencyIds`, `status`가 필수다. 참조 배열의 중복을 거부하고 모든 참조는 같은 문서에 존재해야 한다. 설명과 완료 조건 배열은 정보 부족 후보를 보존하기 위해 비어 있을 수 있다. **빈 완료 조건은 실행 준비의 증거가 아니며 향후 실행 계층에서 기본 실행을 차단해야 한다.**
- 개발 버전은 0 이상의 정수 세 개를 점으로 연결한다. 전체 입력은 최대 1024자이며 각 구성요소의 선행 0은 정규화한다. 사전식이나 부동소수점으로 비교하지 않는다. 존재하지 않는 선행 이슈, 순환, 더 높은 버전의 선행 이슈는 거부한다.
- 교환 가능한 상태는 `ready`, `retryable`, `failed`, `needs_review`, `completed`다. 실행 중 상태는 가져올 수 없다. 여기의 `completed`는 **문서 작성자의 주장**이며 이 로컬 프로젝트에서 확인된 완료나 선행 조건 충족을 뜻하지 않는다. 이후 등록 기능은 가져온 상태와 로컬 검증 상태를 분리해야 한다.

## 연결 시 요구사항

파서의 성공은 문서의 구조·참조가 계약에 부합한다는 뜻이다. 원본 자료의 진위나 의미적 완전성, 실제 코드의 구현 상태, 사용자의 실행·승인 의사는 검증하지 않는다. 내부 저장소는 프로젝트 소속, 문서 ID 충돌, revision, 트랜잭션을 확인한다. 추후 외부 요청 및 실행 경로에서는 사용자의 권한과 신뢰 경계를 별도로 확인해야 한다. 정책·권한·실행 설정은 이 교환 형식에 포함하지 않는다.

내보내기 파일 생성은 별도 사용자 행위다. 직렬화는 파일을 쓰지 않는다. 현재 저장 계층은 프로젝트 안에서 네이티브 저장창으로 선택한 **새 파일**만 만들며 기존 대상은 덮어쓰지 않는다. 현재 문서의 교환 데이터에 있던 상태를 그대로 내보내므로 가져온 `completed` 표시는 로컬 완료의 증거가 아니다. 기존 파일의 해시·revision을 확인한 교체 및 동기화는 아직 제공하지 않는다.

내보내기는 가독성을 위해 들여쓴 JSON을 우선 사용한다. 들여쓰기로 4 MiB 제한을 넘으면 같은 데이터를 공백 없는 JSON과 최소 fenced 블록으로 내보낸다. 내용이나 참조를 줄여 부분 성공으로 표시하지 않으며, 최소 표현도 제한을 넘으면 오류로 처리한다.
