# 대화별 스킬 배정과 읽기 전용 실행 계획

## 목표와 범위

- 사용자가 일반 작업에서 읽기 전용을 명시적으로 선택하고 Team/Solo 실행의 sandbox와 승인 정책에 반영한다. 기존 클라이언트의 필드 누락은 현재 동작을 유지한다. Atelier 제작은 별도 기능이며 이 선택을 암묵적으로 전달하지 않는다.
- 후속 대화의 짧은 요청은 현재 대화에서 완료된 최근 사용자 요청의 제한된 맥락만 참고해 스킬을 선택한다. 현재 요청의 명확한 도메인·명시 선택을 우선하고, 과거 응답·다른 대화·실패한 실행의 텍스트는 선택 근거로 쓰지 않는다. 대화 맥락은 권한을 확장하지 않는다.
- 조사 모드에서는 선택한 프로젝트를 가장하지 않고 App Server에서 확인된 사용자/시스템 범위의 활성 스킬만 제공한다. 접근 범위가 불명확한 스킬은 제외하고 목록 실패를 표시한다. 기존 네트워크 기본 차단과 읽기 전용 정책을 보존한다.
- 다른 프로젝트에는 해당 프로젝트와 사용자 설정의 스킬을 우선하고, 앱 저장소에서 실제 경로와 이름이 확인된 공통 스킬만 보조 후보로 추가한다. 이름이 같으면 선택한 프로젝트의 스킬이 우선한다. 조사 모드에는 이 프로젝트 범위 스킬을 자동으로 추가하지 않는다.
- 스킬 선택 이유, 기본 에이전트 fallback, 수동 선택과 기존 대화 저장 형식의 호환성을 보존한다.

## 구현 순서

1. `turn.start`에 선택적인 읽기 전용 설정을 추가하고 서버에서 타입을 검증한다. UI는 일반 작업에서 명시적으로 선택할 수 있게 한다. 조사 모드는 항상 읽기 전용임을 표시한다.
2. 브리지는 실행별 설정을 고정하고 Team 계획·작업과 Solo turn에 반영한다. 읽기 전용에서 추가 실행 권한 요청은 거절하며 UI 선택 변경이 실행 중 정책을 바꾸지 못하게 한다.
3. 독립적인 라우팅 함수를 추가해 명확한 현재 요청을 우선한다. 모호한 후속 요청에만 같은 대화의 최근 완료된 사용자 요청을 제한적으로 적용하고, Team에서는 각 Task 역할과 현재 작업 내용도 함께 검사한다.
4. 프로젝트별 목록에 검증된 앱 공통 스킬을 보완하고, 조사 모드의 스킬 목록 조회와 화면을 연결한다. 출처가 프로젝트나 미상인 스킬은 조사 모드에서 자동·수동 배정하지 않는다.
5. 단위·통합 테스트로 입력 거부, 권한 확대 거절, 대화 격리, 도메인 전환, 수동 모드, 목록 필터링, 기존 계약 호환을 확인한다. 가능한 로컬 UI에서 키보드와 화면 크기를 점검한다.

## 위협과 검증 경계

보호 대상은 사용자 파일과 권한, 대화 간 문맥, 스킬의 실제 출처다. 브라우저 입력·모델 출력·이전 응답은 비신뢰이며 추가 권한의 근거가 아니다. 명시적 읽기 전용은 서버가 실행별로 고정하고 sandbox 및 거절 경로에서 강제한다. 별도 프로세스나 외부 서비스의 MCP 도구는 sandbox 밖에서 동작할 수 있으므로 이 설정만으로 해당 도구의 쓰기나 외부 부작용을 막는다고 보장하지 않는다. 현재 요청이 과거 맥락과 충돌하면 현재 요청을 우선한다. 목록 필터는 서버에서 수행한다. 스킬 배정이나 테스트 통과가 모델의 정확성·UI 완성도를 보장하지는 않는다.

## 확인과 복구

관련 단위 테스트와 합성 App Server 통합 테스트를 먼저 실행하고 `npm run typecheck`, `npm test`, `npm run build`를 실행한다. `node tools/verify-codex-skill-discovery.mjs <설치된-codex-실행파일-절대경로>`는 격리된 합성 Codex 홈에서 실제 CLI의 스킬 범위 응답을 확인하며 모델을 호출하지 않는다. 실제 모델·모바일 기기·시각 검증은 실행한 범위만 보고한다. 데이터 마이그레이션은 없으며 새 필드는 선택적이다. 문제가 생기면 관련 코드 변경을 되돌리고 다시 빌드·재시작한다. 기존 대화 저장 데이터는 이전 형식으로 읽을 수 있어야 한다.
