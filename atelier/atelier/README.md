# Atelier — 로컬 디자인 가이드

아이디어·이미지·정한 컨셉·기존 결과에서 출발해, 제품과 사용자 흐름을 정리하고 확정된 디자인 프롬프트를 만드는 로컬 MVP입니다. 게임이나 네컷 서비스를 제작하는 앱은 아닙니다.

처음 사용한다면 기본 **가이드 보기**에서 시작하세요. 제품 설명 → 만들 기능 → 사용 순서 → 화면 스타일 → 요약 확인으로 이어집니다. 짧은 [사용 가이드](사용가이드.md)와 [1.2 UX 개선·검증 기록](docs/UX-1.2.md)을 제공합니다.

## 실행

**Node.js 22.13 이상**이 필요합니다. 별도 패키지 설치, API 키, 계정, 외부 AI 연결은 필요 없습니다.

Windows에서는 `start.cmd`를 두 번 클릭합니다. 또는 이 폴더에서:

```powershell
npm start
```

브라우저에서 **http://127.0.0.1:4317** 을 엽니다. 서버를 켜 둔 동안 사용할 수 있습니다. 서버 종료는 실행한 터미널에서 `Ctrl+C`입니다. 포트 변경은 PowerShell에서 `$env:PORT='다른포트'; npm start`를 사용합니다.

데이터는 `data/atelier.sqlite`, 원본·크롭·결과 이미지는 `data/files/<프로젝트 ID>/`에 저장합니다. 폴더째 옮기거나 앱의 JSON 백업·복원으로 프로젝트를 이동할 수 있습니다. 제공된 QA 예시는 실제 고객 조사나 외부 서비스의 제작 결과가 아닙니다.

## 1.2에서 바꾼 기본 경험

사진 서비스로 고정된 유형별 예시를 제거했습니다. 행동 중심의 사용 순서를 직접 쓰거나 골라 수정하며, 출처·근거·연결 관계는 상세 편집에서 엽니다. 스타일을 고른 다음에만 선택 이유를 묻고, 결과 확인 기준은 체크로 정합니다. 이미지·컨셉·기존 결과에서 시작해도 필요한 첫 행동이 다릅니다.

## 1.1에서 보완한 기능

분기·복구의 구조화와 경로 검사, 명시적 근거 관계에 따른 영향 전파, 실제 흐름·화면·리소스 ID로 선택하는 출력, 문서·데이터·서체·SVG·ZIP 첨부를 추가했습니다. 이전 스냅샷은 보존합니다. 자세한 조작과 검증은 [보완 구현 기록](docs/EXTENSION.md)을 확인하세요.

## 사용 흐름

1. 시작점과 이름·자유로운 설명으로 프로젝트를 만듭니다. 기본 가이드는 지금 정할 내용만 보여 줍니다.
2. 예시를 보거나 직접 작성합니다. 예시는 **제안**, 직접 확인한 항목은 **확정**으로 구분합니다. 자동 저장은 확정과 다릅니다.
3. 흐름의 시작·완료 지점과 실제 분기·복구 연결을 확인하고, 필요하면 레퍼런스 원본을 등록해 드래그로 영역을 지정합니다. 관찰·해석·적용 대상·이유를 구분합니다.
4. 컨셉과 팔레트·서체·컴포넌트 샘플을 비교하고 적용 범위를 정합니다.
5. 브리프에서 누락·파일·명시적 값 충돌을 보완하고 자신의 의도를 직접 확인합니다.
6. 서비스 전체/선택한 흐름/선택한 화면/선택한 리소스를 실제 대상으로 지정하고 통합 프롬프트를 조립합니다. 해당 스냅샷의 원본·크롭·실제 문서·서체를 포함한 ZIP을 가져갑니다.
7. 외부 도구에서 직접 제작한 결과를 해당 프롬프트 버전에 연결해 등록합니다. 실제 출처와 화면·실행 기록을 적습니다.
8. 고정 기준에 기대·관찰·근거·판정을 남기고, 차이를 수정 계획과 새 통합 프롬프트로 연결합니다. 새 결과는 같은 기준과 이전 일치 항목을 다시 확인합니다.

여덟 탭과 가이드/상세 편집은 같은 데이터를 사용합니다. 보완 후 돌아오기와 재접속을 지원합니다. 공통 기준은 설정에서 직접 선택한 경우에만 다른 프로젝트의 기본값으로 재사용합니다.

## 검증

```powershell
npm run check
npm test
```

Node 내장 테스트 러너로 53개 도메인·경로·의존 관계·SQLite 재시작·이미지 및 비이미지 파일·복원·프로젝트 분리·범위별 실제 ZIP을 검증했습니다. 테스트 서버는 별도 임시 데이터 디렉터리와 포트 14317·14318을 사용하고 종료 후 정리합니다.

`tests/browser-journey.js`는 제공된 Playwright page로 실행한 전체 UI 검증 시나리오입니다. 일반 `npm test`에는 브라우저 설치를 요구하지 않습니다. 확장 기능의 실제 UI 시나리오는 `tests/browser-extension.js`입니다. 두 스크립트의 픽스처 경로는 이 작업 공간 기준 절대 경로이므로 다른 위치에서 브라우저 재검증할 때 수정합니다.

- [AC01~AC64 구현·검증 대응표](docs/ACCEPTANCE.md)
- [실제 검증과 제한](docs/VALIDATION.md)
- [참고 디자인 관찰과 적용](docs/DESIGN.md)
- [외부 연결 경계](docs/BOUNDARIES.md)

## 지원 범위와 제한

개인용 로컬 실행을 지원합니다. 등록 파일당 15MB, 자체 JSON 백업은 요청 전체 90MB 이내입니다. 레퍼런스·크롭·결과는 PNG/JPEG/WebP입니다. 콘텐츠와 리소스는 PDF·텍스트/Markdown·JSON/CSV/TSV/XML·SVG·WOFF/WOFF2/TTF/OTF·ZIP·Office 문서·일부 게임/미디어 형식을 지원합니다. 전체 지원 목록은 `public/resource-types.js`에 있습니다. 목록 밖의 형식은 ZIP 자료로 묶거나 별도 제공 계획을 기록합니다. 문서·아카이브의 내용을 자동 실행하거나 압축 해제하지 않습니다.

명시적 값·필수 입력·파일 관계는 프로그램이 검사합니다. 분위기와 목적의 적합성, 실제 스타일 일치, 원인과 개선은 사용자가 판단합니다. 실제 초보 사용자 독립 진행 검토(AC54), 보조기기와 전체 OS/브라우저 조합 검증은 아직 필요합니다. 외부 제작을 자동 실행하거나 진행률을 알 수 없습니다.

전체 JSON 백업은 모든 프로젝트 데이터와 이력을 복원합니다. 범위별 ZIP의 `handoff.json`은 외부 전달용이며 자체 백업 복원 형식이 아닙니다. 이전 프로젝트의 자유 입력 범위·분기 메모는 보존하지만 새 출력 전 실제 연결과 대상을 확인해야 합니다.

## 구성

- `public/easy-guide.js`: 단계별 기본 가이드, 범용 행동 예시, 동일 결정의 확인 작업
- `public/guide.js`: 버전 있는 질문·제품 유형별 예시·로컬 시각 샘플
- `public/domain.js`: 결정 상태·규칙 검사·프롬프트·검토 회차
- `public/structure.js`, `panels.js`: 분기 그래프·의존 관계·범위 선별과 편집 패널
- `public/resource-types.js`: 클라이언트·서버가 공유하는 첨부 형식
- `public/app.js`, `styles.css`: 여덟 작업 영역과 반응형 UI
- `server.mjs`: 로컬 HTTP·SQLite·원본 파일·백업 복원
- `src/project-validation.mjs`, `resources.mjs`, `zip.mjs`: 백업·관계·파일 형식 검증과 실제 ZIP 생성
- `contracts.d.ts`: 도메인 및 후속 연결의 개념적 데이터 계약

코드는 의존성 없는 ES 모듈 JavaScript이며 타입 계약을 함께 제공합니다. SQLite는 Node 22 내장 실험적 API를 사용하므로 실행 시 experimental 경고가 표시될 수 있습니다.

아이콘은 [Streamline Pixel](https://www.streamlinehq.com/icons/pixel)의 공식 공개 SVG입니다. **Free icons from [Streamline](https://streamlinehq.com)**. 영문 서체는 Instrument Serif / Instrument Sans (SIL OFL), 한글은 가용 시스템 서체를 사용합니다. 출처와 라이선스는 `public/assets/` 및 `docs/LICENSES.md`를 확인하세요.
