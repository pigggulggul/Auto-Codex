# 1.2 UX 개선과 검증 · 2026-10-29

기본 화면을 `public/easy-guide.js`로 다시 구성했다. 결정 ID·파일·변경 이력·스냅샷·검토 회차는 기존 상세 편집과 공유한다. 외부 AI나 커넥터는 추가하지 않았다.

## 피드백에 따른 변경

| 문제 | 변경과 데이터 연결 |
|---|---|
| 추상적인 질문·근거·관계 편집이 첫 화면부터 등장 | 제품 설명과 기능을 두 단계로 분리. 근거·관계는 상세 편집으로 이동. fields/decision ID 공유 |
| Q21 ‘의문·근거’ 이해 어려움 | 첫 사용자의 안내·상태 설명·실수 복구·아직 모름 중 선택. 가설과 내장 방안으로 기록하며 실제 조사로 표시하지 않음 |
| 컨셉을 정하기 전 Q22 질문 | 선택한 컨셉이 있을 때만 이유 노출. 컨셉 ID와 fit 연결 |
| Q16 ‘무엇이 잘 되었는가’ 모호 | 완성한 화면의 시작·상태·완료·실패·긴 한글을 체크. 직접 추가한 기준도 criteria에 기록 |
| Q05와 기능 범위 용어 혼란 | 반드시 지킬 조건은 선택 입력. 지금 만들 기능과 나중에 만들 기능으로 구분 |
| 제작 도구=네컷, 게임=생존 게임으로 고정 | 일반 유형 예시를 범용으로 교체. 명시적인 데모 프로젝트에서만 기존 사례 사용 |
| ‘실제 연결과 분기’ 이해 어려움 | 이전 선택을 바꾸거나 실패했을 때 갈 곳 선택. 실제 단계 ID 사이 next/branch/recovery/loop 연결로 저장 |
| 이미 입력한 값을 재요구 | 사용자·핵심 작업을 고객·가치 정보에 재사용하고 이유/연결 기록. 기본 구매·로그인·결제는 추가하지 않음 |
| 이미지·컨셉에서 시작한 후 긴 누락 목록 | 등록한 관찰/방향은 보존하고 필요한 제품 설명으로 연결 |
| 기존 결과 개선의 과도한 입력 | 기대·불편부터 시작하고 실제 결과 등록. 한 기준씩 비교. 수정 계획은 변경·범위·유지·재검토 중심 |
| 색 코드·영문 서체 이름 어려움 | 색상 선택기, 고딕/명조/고정폭, 모서리 선택. 색은 즉시 샘플에 반영 |
| 모바일 편집 모드 전환 불가 | 가이드·상세 양쪽에서 전환 표시. 같은 스타일 ID의 값을 왕복 확인 |

밝은 바탕·차콜 본문·핑크 강조와 Instrument 서체의 제목/본문 역할은 유지했다. 작업 입력·설명은 13~14px 중심으로 키우고 한 작업 열로 구성했다. 영문 장식 제목은 줄이고 실제 행동을 한글 제목으로 크게 표시했다. 제품별 스타일은 비교 샘플에만 적용한다.

## 네 프로젝트의 실제 브라우저 조작

| 프로젝트 | 시작 경로 | 직접 입력한 사용 순서 | 실제 연결 수 |
|---|---|---|---:|
| DI/DO 보드 상태 변환 시뮬레이터 | 아이디어부터 | 상태 확인 → DI 변경 → 규칙 적용 → DO·로그 확인 | 10 |
| 라이어 게임 디자인 | 이미지부터 | 참가자 설정 → 역할 비공개 확인 → 대화 → 투표 → 공개 | 14 |
| 이상형월드컵 사이트 UI | 컨셉 확정 | 주제 선택 → 비교 → 선택 → 다음 대결 → 우승자 | 13 |
| 앙케이트 사이트 UI | 기존 결과 개선 | 질문 읽기 → 시간 선택 → 제출 → 완료 → 집계 | 13 |

제품 설명·사용자·목표·기능·순서·프로젝트별 확인 기준을 직접 입력하고 최종 프롬프트를 만들었다. 새로고침 뒤 기록을 확인했다. 촬영·네 장·꾸미기·채집·거점 요구가 섞이지 않았다. 네 프로젝트 모두 파일 포함 백업을 실제 복원하여 SHA-256·원본/영역·단계·스냅샷 관계가 보존되고 원본 프로젝트가 변경되지 않았음을 확인했다. 전달용 ZIP의 실제 헤더와 prompt.md도 확인했다.

`tests/browser-ux.js`에 세 시작 경로의 UI 조작, `tests/browser-ux-revision.js`에 수정·모바일 조작을 기록했다. DI/DO 최초 입력은 도구에서 직접 수행했다. 스크립트는 이 작업 공간의 로컬 QA 파일과 프로젝트 ID를 사용한다. `npm test` 53개와 실행 모듈 문법 검사 14개가 통과했다.

## 수정과 재검토

직접 렌더한 테스트 HTML을 이미지로 등록했다. 실제 보드·게임·설문 서비스를 만들었다고 표시하지 않았다. 파란 버튼을 기대하는 기준과 초록 버튼이 있는 화면을 비교하고 변경·유지·재검토 조건으로 수정 계획을 저장했다. 수정 프롬프트와 수정 HTML 이미지를 등록해 이전 회차 및 동일 기준으로 이어지는지 확인했다.

관찰한 스타일만 일치/해결됨으로 기록했다. 다른 7개 기준은 확인 불가이며 전체 검토는 완료하지 않았다. 이전 스냅샷은 보존했다. 모바일 전환 문제를 수정한 뒤 수정 시나리오 전체를 다시 실행해 통과했다.

## 화면 확인과 수정

1440×1000과 390×844에서 실제 화면을 저장하고 이미지를 열어 확인했다. 긴 한글 제목·실제 입력·흐름 선택·레퍼런스·색과 글자·한 기준씩 비교하는 화면을 확인했다. 390px 문서 가로폭도 390px이었다. 강조색 실시간 미리보기와 상세 편집에서 같은 결정 ID를 바꾼 뒤 돌아오는 과정도 확인했다.

검증 중 중복 재검토 표시, 샘플 키가 결정 ID를 덮어써 발생한 저장 오류, 모바일 모드 전환 숨김을 발견해 고쳤다. 수정 후 네 프로젝트 및 수정·모바일 시나리오를 다시 진행했다. 최종 세 시나리오 실행의 페이지 오류와 외부 요청은 0이었다.

최신 기본 화면은 `20-first-task.png`, `21-mobile-first-task.png`, `22-mobile-style.png`다. `12`~`19`는 단계별 기능 확인 화면이다. `12`·`13`은 최종 화면으로 다시 저장했다. 실제 ID·출력 크기·백업 검증은 `ux-scenarios.json`에 있다.

## 남은 검증

실제 초보 사용자를 모집해 이해도·완료율·난이도를 측정하지 않았다. 모든 사람이 막힘 없이 사용한다고 판정하지 않는다. 전체 키보드/스크린리더 접근성 검수, 실제 제작한 네 제품의 동작·하드웨어·게임 규칙·설문 집계도 검증하지 않았다. 이번 검증 대상은 디자인 가이드의 입력·결정·출력·파일·수정 계보다.

AC01~AC64 대응표는 `ACCEPTANCE.md`에 유지하며 이번 변경은 이 문서와 `easy-guide.test.mjs`로 보완한다. AC54 초보 사용자 검토는 계속 확인 필요다.

후속 외부 서비스 연결 경계는 `domain.js`의 결정/스냅샷 생성, 로컬 `/api`의 파일 저장, 템플릿 출력에 분리되어 있다. 활성 커넥터·가짜 응답·API 키 입력은 없다.
