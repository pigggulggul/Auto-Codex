# 1.2 최신 검증

2026-10-29: 자동 테스트 53개 통과, 실행 모듈 문법 검사 14개 통과. 네 프로젝트의 실제 입력·선택·출력, 파일 백업·복원, 수정 결과의 같은 기준 재검토, 1440px/390px 화면을 확인했다. 최신 근거는 [UX 개선·검증](UX-1.2.md)과 [데이터 기록](ux-scenarios.json)을 본다. 아래는 이전 버전의 검증 기록이다. 실제 초보 사용자 조사는 계속 미수행이다.

# 검증 기록 — 2026-10-29

## 실제 실행 환경

Windows, Node.js v22.18.0, Node 내장 SQLite, HTTP 127.0.0.1:4317에서 앱을 실행하고 실제 브라우저를 열었다. npm 설치나 외부 런타임 패키지는 사용하지 않았다.

`npm run check` 구문 검사를 수행했다. `npm test`의 도메인·저장·파일 테스트 **45개가 통과**했다. 주요 검증은 상태가 실제 데이터와 출력에 이어지는지에 대한 것이며 버튼의 존재만 확인하지 않았다.

## 도메인과 실제 서버 검증

- 네 시작 경로의 입력 원문과 미정 상태, 첫 작업 연결
- 제안·제외의 출력 필터링, 동일 입력·템플릿의 결정적 문서 조립
- 고객과 제공 가치·의문·흐름·스타일 범위·레퍼런스 적용의 통합 출력
- 같은 역할·범위의 명시적 값 충돌 차단
- 변경된 상위 결정에만 영향 표시, 과거 문서·기준 불변
- 실제 파일 바이트·SHA-256·프로젝트 소유 관계·크롭 참조
- SQLite 서버를 종료하고 다시 실행한 후 스냅샷·파일 유지
- 오래된 창의 저장 충돌 차단, 기존 스냅샷 수정 차단
- 올바른 백업 복원과 파일 누락·손상·지원하지 않는 버전 거부
- 실제 PNG 바이트와 프롬프트가 들어 있는 ZIP의 헤더·CRC32·구성
- 실제 결과/고정 기준/수정 계획/수정본/재검토의 버전 관계
- 근거 없는 완료·의도 불일치·실행 기록 없는 동작 완료 차단

## 실제 브라우저 흐름

`tests/browser-journey.js`를 Playwright page에서 실행해 다음 전체 흐름이 통과했다.

1. 네 시작 경로에서 프로젝트 생성 후 실제 편집 화면과 원문 확인.
2. 공주풍 네컷 예시에서 프로젝트 질문·기능·화면·흐름·스타일을 직접 확정.
3. 실제 PNG를 원본으로 등록, 마우스 드래그로 비율 좌표 영역과 별도 PNG 크롭 생성.
4. 관찰·해석·적용 대상·이유·유지·변경을 직접 입력하고 확정.
5. 추가 지시를 입력한 뒤 브리프 의도 확인, 통합 프롬프트 생성. 고객·의문·범위·추가 지시가 문서에 들어간 것을 데이터로 확인.
6. 실제 ZIP 요청 성공과 바이너리 헤더 확인.
7. QA 결과 이미지를 지정 버전에 등록, 기본 판정이 모두 확인 불가인지 확인.
8. 관찰과 근거·판정을 직접 입력하고 수정 계획→최신 수정 통합 프롬프트 생성.
9. 수정 결과를 새 버전에 등록, 이전 회차 연결과 동일 기대 기준·초기화된 새 판정 확인.
10. 근거 없는 완료 차단, 새로고침 후 검토 위치·이미지 유지 확인.
11. 백업을 새 프로젝트로 복원해 원본·크롭·결과 2개와 회차 관계 확인.
12. 이 전체 과정에서 외부 요청을 차단했고 외부 요청은 **0건**이었다.

추가 브라우저 검증:

- 수정 계획 작성 중 스타일 보완으로 이동한 뒤 원래 작업으로 복귀하고 임시 계획 입력이 그대로 이어지는 것을 확인했다.
- 저장 PUT 요청을 의도적으로 실패시켜 화면 입력과 브라우저 임시 입력이 유지되는 것을 확인했다. 요청을 복구하고 재저장·새로고침 후 같은 값을 확인했다.
- 실제 게임 예시를 별도로 생성해 반복 루프·게임 상태·스타일 분리를 확인했고, 도메인 테스트에서 두 제품을 모두 통합 출력했다.
- 키보드 Tab의 대화상자 내부 순환과 Escape 닫기를 실제 실행했다.
- 원본 교체 후 이전 영역의 소속을 검사하고, 새 크롭과 별도 재검토를 요구하는 도메인 검증을 추가했다.
- 자체 백업 파일을 UI의 복원 입력으로 직접 등록해 원본·크롭·검토 2회차가 복원되는 것을 확인했다. 프롬프트 문단의 결정 추적 버튼에서 같은 제품 입력 위치로 이동하는 것도 확인했다.

## 화면 확인

참고 사이트를 실제 열어 백색·짙은 회색·핑크 포인트, Instrument Serif/Sans, 넓은 여백과 옅은 표면을 관찰했다. 초기·스크롤 위치와 computed font-family를 확인했다. 원본의 마우스 추적 구현은 확인하지 못했으며 시작 화면의 작은 포인터 메모는 추가 설계로 구분했다.

1440×1000 데스크톱, 768×1024 태블릿, 390×844 모바일에서 화면을 열었다. 문서 scrollWidth는 각각 1425, 753, 375 CSS px로 가로 넘침이 없었다. 모바일에서 메뉴를 열어 작업 탭을 변경하고 주요 동작을 사용했다.

다음 PNG를 실제 열어 한글·선택·제안·빈 상태·작업 구조를 확인했다.

- `01-home.png`: 시작 경로와 작업 목록
- `02-design.png`: 게임 예시와 질문, 가이드·근거 위계
- `03-concepts.png`: 공주풍 사진 컨셉 두 방향과 비교용 샘플
- `04-reference.png`: 실제 원본과 비율 영역
- `05-review.png`: 당시 기준과 결과 비교, 재검토 상태
- `06-mobile-review.png`: 모바일 결과 비교
- `07-mobile-style.png`: 모바일 팔레트·표현 규칙

등장 애니메이션이 끝나기 전에 찍힌 QA 스크린샷은 교체하고 opacity=1 이후 다시 캡처했다. 시작 화면 장식 카드의 글줄 넘침은 제목 크기를 줄여 수정했다. 어두운 팔레트 견본의 레이블은 밝은 글자로 조정했다. prefers-reduced-motion에서는 등장·마우스 장식을 해제한다.

## 검증 범위 밖

- 실제 초보 사용자에게 다음 탭을 알려 주지 않고 수행시키는 AC54 사용성 연구
- 실제 외부 제작물의 스타일 품질·고객 반응·상품성 판단
- 스크린리더를 통한 전체 접근성, 전체 Windows/macOS/Linux·브라우저 조합
- 브라우저 보안 정책 차이에 따른 클립보드 동작 전체 조합 (실패 시 수동 복사 경로 제공)
- 명시한 첨부 지원 목록 밖의 형식, 90MB를 넘는 백업, 장기간의 큰 프로젝트 데이터

원본·크롭·결과 파일은 프로젝트별 디렉터리로, 프로젝트와 버전은 SQLite로 보존된다. 테스트의 시각 이미지들은 **테스트용 픽스처**이며 실제 외부 서비스의 성공 응답이나 완성된 고객 결과로 표시하지 않았다.
