# Atelier 사용 가이드 · 1.2

`start.cmd`를 실행하고 `http://127.0.0.1:4317`을 엽니다. 기본은 **가이드 보기**입니다. 지금 정할 내용과 다음 행동만 따라가면 됩니다.

## 가지고 있는 것부터 시작하세요

| 시작 버튼 | 처음 하는 일 | 그다음 |
|---|---|---|
| 아이디어부터 | 제품, 사용자, 마칠 작업, 사용할 기기 선택 | 이번에 만들 기능 |
| 이미지부터 | 이미지 등록 → 부분 선택 → 특징·사용할 곳·도움 적기 | 만들 제품 설명. 관찰은 보존 |
| 컨셉 확정 | 정한 화면 방향 작성 → 선택 이유 고르기 | 만들 제품 설명. 컨셉은 보존 |
| 기존 결과 개선 | 기대한 화면과 불편한 점 → 실제 결과 등록 | 한 기준씩 비교하고 수정 계획 |

이미지나 컨셉이 없어도 됩니다. 기존 결과 개선은 모든 제품 질문을 먼저 채우지 않아도 시작할 수 있습니다.

## 아이디어에서 프롬프트까지

1. **제품 설명**: “누가 무엇을 하는 제품”인지 적습니다. 처음 적은 원문을 눌러 사용할 수 있습니다. 사용자와 기기는 선택지로 고를 수도 있습니다.
2. **지금 만들 기능**: 한 줄에 하나씩 적습니다. 여기에 적은 기능만 이번 디자인에 포함합니다. 나중에 만들 것은 선택 항목에 적어두세요. 첫 사용자에게 필요한 안내·상태 설명·실수 복구 중 고릅니다. 몰라도 “첫 사용에서 확인”을 선택할 수 있습니다. 실제 자료가 없으면 준비 계획으로 진행합니다.
3. **사용 순서**: 행동을 한 줄에 하나씩 적습니다. 상태 조작·라운드 게임·두 후보 비교·질문 응답 등 내장 예시를 고쳐 써도 됩니다. ‘이전 선택을 바꾸려 하면?’과 ‘실패하면?’을 골라 실제 이동·재시도 연결을 만듭니다. 한 화면 안의 여러 행동이어도 됩니다.
4. **레퍼런스**: 있으면 등록하고, 없으면 다음으로 진행합니다. 관찰은 직접 적습니다. 이미지 자동 분석은 하지 않습니다.
5. **화면 스타일**: 내 프로젝트 이름과 작업으로 표시한 샘플을 비교하거나 직접 방향을 적습니다. 방향을 고른 다음 작업에 맞는 이유를 선택합니다.
6. **색과 글자**: 색상 선택기, 글자와 모서리 선택으로 바꿉니다. 배치·표면·움직임 제안도 접힌 부분에서 확인합니다. 완성한 화면에서 확인할 것을 체크하고, 프로젝트만의 기준을 추가해도 됩니다.
7. **최종 요약**: 앞에서 적은 내용을 읽고 틀린 곳만 보완합니다. ‘요약 확인했어요’ 다음에 프롬프트 만들기를 누릅니다.

DI/DO 프로젝트라면 “상태 확인 → DI 변경 → 규칙 적용 → DO·로그 확인”, 라이어 게임이라면 “참가자 설정 → 역할 확인 → 대화 → 투표 → 공개”로 직접 바꿉니다. 촬영이나 사진 선택 기능은 자동으로 들어가지 않습니다.

## 헷갈렸던 항목은 이렇게 바뀌었습니다

| 이전 표현 | 이제 하는 일 |
|---|---|
| 그 의문에 무엇으로 답하나요? | 첫 사용자에게 필요한 안내·상태 설명·실수 복구 중 선택. 아직 모름도 가능 |
| 이 분위기는 왜 어울리나요? | 스타일을 고른 뒤, 작업에 맞는 이유 선택 |
| 무엇을 보면 잘 되었나요? | 완성한 화면의 시작·상태·완료·재시도 등을 체크 |
| 꼭 유지하거나 피할 조건 | 반드시 지킬 조건이 있을 때만 여는 선택 입력 |
| 이번 범위 / 후속 범위 | 지금 만들 기능 / 다음 버전에서 검토할 기능 |
| 실제 연결과 분기 | 이전 선택을 바꾸거나 실패했을 때 갈 단계 선택 |
| 근거·출처·영향 관계 | 필요한 경우 상단 ‘상세 편집’에서 확인 |

상세 편집의 미정·제안·확정·제외는 아직 정하지 않음·후보·확인한 요구·사용하지 않음입니다. 제외한 내용은 확정 요구로 출력하지 않습니다.

## 결과를 받아 수정할 때

프롬프트와 실제 자료 ZIP을 외부 제작 도구에 직접 전달하세요. 이 앱은 제작을 실행하거나 진행률을 조회하지 않습니다.

결과가 나오면 **자가 진단과 수정 → 실제 결과 등록**에서 이미지 또는 직접 실행한 기록을 등록합니다. 어떤 프롬프트 버전으로 만든 결과인지 고릅니다.

한 번에 한 기준씩 기대·실제 관찰·확인한 위치/실행 기록·판정을 적습니다. 모르면 확인 불가로 두세요. 바꿀 항목만 수정 계획에 포함합니다. 바꿀 모습·대상·유지할 것·재검토 방법을 적고 수정 프롬프트를 만듭니다.

수정 결과도 다시 등록해야 합니다. 이전 판정은 복사하지 않고 같은 기준으로 새로 확인합니다. 일부 스타일을 확인했어도 전체 서비스가 완료되는 것은 아닙니다.

## 저장하고 다시 시작하기

자동 저장과 요구 확정은 다릅니다. 단계 끝의 확인 버튼으로 내용을 확정합니다. 입력은 자동 저장되며 마지막 작업에서 다시 열립니다.

- **데이터와 원본 백업**: 프로젝트 기록과 원본·크롭·결과·첨부 파일을 함께 보관하는 JSON입니다. 홈에서 새 프로젝트에 복원합니다.
- **참고 자료 ZIP**: 선택한 프롬프트와 그때 전달할 자료입니다. 전체 프로젝트 백업을 대신하지 않습니다.
- **저장 실패**: 입력을 유지합니다. 다시 저장하거나 임시 입력을 내려받습니다.

여덟 탭은 자유롭게 이동합니다. 가이드와 상세 편집은 같은 결정 ID를 사용합니다. 기존 내장 흐름이 맞지 않으면 사용자 흐름에서 ‘이 흐름은 사용하지 않기’를 누르고 원하는 순서를 작성하세요. 이전 기록은 보존됩니다.

`examples/DI-DO.atelier.json`, `liar.atelier.json`, `worldcup.atelier.json`, `survey.atelier.json`은 조작 검증에 사용한 가상 프로젝트 백업입니다. 실제 고객 조사나 완성된 외부 제품은 아닙니다.
